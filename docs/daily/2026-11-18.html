Search clicks and the cost of review

Desktop search experiments and engineering-adoption studies measure different downstream effects. Their samples and identification limits matter.

RevScope reviews evidence that Google AI Overviews reduce visits to outside sites, distinguishing a desktop randomized experiment from observational search panels. The reported roughly forty-percent reduction applies to searches that would display an Overview, not to all search traffic or every publisher. The working-paper result is not yet peer reviewed and does not cover mobile. Separate citation and ranking correlations do not prove which optimization tactics cause inclusion. The article also promotes RevScope, so its commercial interest and the original studies matter when interpreting its recommendations. (read more).

ComplexDiscovery reports a Harvard working paper in which firms adopting coding agents produced more code without a statistically detectable increase in completed Jira issues. Its account describes longer pull-request review times and more change requests, suggesting that faster drafting can move a constraint downstream. The study compares adoption timing rather than randomly assigning firms, so its causal interpretation depends on procurement and other assumptions. A statistically indistinguishable result is not proof of exactly zero benefit. The article extends the review-checkpoint idea to legal tools, but the study itself examines software firms, not legal work. (read more).

Separating generated code from its executor

An external sandbox design narrows one execution boundary, while split inference assigns prompt processing and response generation to different hardware.

Simon Willison introduces an external-sandbox pattern in which a coding agent remains outside the environment that executes its generated code. Three demonstration implementations expose a common local API, with optional network allow-listing and credential replacement. The separation offers a way to compare isolation approaches, not proof that any agent workflow is safe. Its value depends on which operations are routed through the sandbox and what the proxy permits. The article describes an experiment and its design; no implementation was installed or security audit performed for this summary. (read more).

Cerebras describes a production inference design that moves prompt processing to AMD GPUs while Cerebras CS-3 systems generate the response. It reports five times the token throughput per megawatt against a CS-3-only baseline on a specified GPT-OSS-120B endpoint, without reducing generation speed in that deployment. This is a company-reported configuration comparison, not a universal efficiency ratio against GPU systems or across models. Partner integration options include an end-to-end stack and a decode-only SDK; wider deployment plans for 2027 are future capacity, not current availability. (read more).

Learning energy and writing weights

Bounded reasoning benchmarks and hand-engineered networks expose useful mechanisms without proving a general replacement for training.

Jacob Strauss tests whether an LLM can set or edit small neural-network weights without an ordinary gradient-descent loop. His examples succeed by expressing familiar templates, linear controllers, word dictionaries and task-specific shortcuts as weights, while an undertrained language-model example improves only slightly. These author-run experiments make some model structure easier to inspect, but do not show that direct weight writing replaces training. Models, task formulations, evaluation access and the author’s subsidized API use constrain comparisons of accuracy, speed and cost. (read more).

Lex Toumbourou tests weight-space programming on a small digit-classification network and compares the resulting feature engineering with pre-deep-learning methods. In three author-run attempts, an LLM constructs filters and classifiers through repeated feedback, with final performance around ninety percent on held-out images. The model does not see test images or test scores during construction, but it receives training feedback after each attempt. The experiment therefore illustrates a constrained search through hand-designed features rather than learning-free general intelligence. Its architecture and rules differ from earlier Go demonstrations, limiting direct comparisons. (read more).

Durable work is not a verified outcome

These mechanics address crash recovery and handoff, not the truth of a model’s diagnosis. Notifications remain at-least-once and can duplicate; the free in-memory queue loses in-flight state on restart, unlike the described hosted durable option.
