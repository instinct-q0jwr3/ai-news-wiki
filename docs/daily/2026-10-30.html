The patch gap, weaponized

An open-weight model turns published-but-unshipped Firefox fixes into working exploits for about $1,000 a version.

A new disclosure shows Z.ai's open-weight GLM 5.3 can identify and exploit Firefox vulnerabilities using security fixes that have been published but not yet shipped to users - the patch gap. In the researchers' experiments, the model built a webpage that, when visited, read a file from the visitor's computer and exfiltrated it with no further interaction; every Firefox version released between September 17 and October 26 was compromisable using only information available at release time. In every successful compromise, GLM 5.3 also found and used an unpublished vulnerability alongside the patch-gap ones. The significance is the democratization curve: exploiting the patch gap used to require significant time, expertise or access to frontier models with advanced cyber capabilities, so few attackers bothered before fixes shipped. A widely available open-weight model now does much or all of the work, in a setup deliberately built to emulate an unsophisticated actor, at a cost of about $1,000 per Firefox version attacked. The team disclosed its findings to Mozilla and discussed mitigations. (read more).

Games as compute

A transformer compiled into DOOM maps and verified against NumPy, and agent swarms loose in Minecraft and Mindustry.

A team reports running AI agent swarms inside Minecraft and Mindustry - games serving as sandboxes for multi-agent coordination experiments. (read more ⚠).

Doomformer compiles integer neural networks into ZDoom maps and executes them inside a running game of DOOM: voodoo dolls (the player copies DOOM spawns for extra player-1 starts) do the arithmetic, while sector light levels and plane heights hold the sums. Python reads every exposed value back from the running engine and compares it against a NumPy integer reference with zero tolerance - one value off by one and the run fails. It is gloriously slow: about 23,000 times slower than NumPy on a small MLP, and a handwritten digit takes 163 seconds of real-time DOOM at the default schedule, or 8 seconds at --opt 3. The demo is interactive: holding FIRE, the marine inks a 3x3 brush of floor cells; READ feeds the 784 pixels into the network and 1,355 voodoo dolls in the same map compute the MNIST inference. Installable with pip, it ships with a proof mode, a doctor command that checks ViZDoom and Freedoom, and a Colab notebook where you draw on a canvas and DOOM classifies the digit. (read more).

Proofs in production

Lasm compiles Lean 4 to WebAssembly so the web app you deploy is the one you proved.

WIRED chronicles formal verification's breakout moment. Stanford researcher Chuyue Sun's team used an AI tool to complete a verification project in under half a day for less than $500 - work that took three highly skilled experts five months manually - and demonstrated the approach on part of the code that encrypts Signal conversations. Results like that are waking up a field that for decades promised mathematically bug-free software but was too laborious for anyone but the most safety-critical shops to afford. Now startups are racing to productize it. Sun joined &Truth, which launched publicly Thursday with $70 million in funding and chief science officer Ilya Sergey arguing that bridges do not collapse because people did the math first - code should be no different; the company aims to verify any programming language eventually. Rival Harmonic, cofounded by Robinhood CEO Vlad Tenev with $295 million raised, announced its math-focused agent Aristotle now verifies C and Verilog hardware designs, evaluating with chipmakers including Nvidia. (read more).

Meta's Catching JiTTests - just-in-time tests generated by LLMs - have graduated from research prototype to production infrastructure. The approach differs from AI code review: instead of reading a diff and opining, the system generates executable tests designed to fail, each demonstrating a concrete behavioral difference the change introduces. That costs more computation than a review pass, but it catches classes of bugs that LLM- or agent-based reviewers miss, and Meta reports engineers catching more bugs with less load and a smaller false-positive rate. The engineering post frames five months of deployment at Meta's scale - hundreds of millions of lines of constantly evolving code - as evidence the technique is applicable beyond the company, positioning generated-tests-that-fail as a complement to, rather than a replacement for, both traditional testing and AI review. (read more).

Lasm compiles ordinary Lean 4 programs ahead of time to WebAssembly, so one Lean codebase can become a Node server, a serverless or edge function, a WASI module or a browser app - and because it is Lean, you can prove properties of the code you deploy. The flagship example is Conduit, the RealWorld Medium clone, written entirely in Lean with 117 proved theorems, all running in CI against each platform's own local runtime or emulator (project policy: CI never deploys to a real cloud account). Node builds get Lean's full runtime - threads, files, processes, sockets - while edge, Bun/Deno, WASI and browser builds run single-threaded without sockets or processes. Lasm ships on npm with Lean, Lake and build tools included, and the README is explicitly written for AI agents, with an llms.txt index and a docs/AI.md of rules to keep agents from wrong turns - fitting the author's thesis that formal verification is the next evolution of software engineering, enabled by LLMs that understand it. (read more).

Phorion's technical writeup of the trojanized Claude Code extension 2.1.313 on the Cursor Marketplace adds a granular look at the implant's setup and persistence logic across macOS, Linux and Windows, and surfaces a bug that blunts the attack on most Macs. The malware tries to check Remote Login state with systemsetup as a standard user; the command prints an administrator-access error but exits with status 0, so the script never sees the 'Off' it waits for and skips enabling SSH entirely. On a Mac without Remote Login already on, the outbound tunnel can still connect to the attacker's server, but anything forwarded back hits a closed local port 22 - the interactive access path is broken even though the attacker's SSH key, the persistence mechanisms and the HTTP beacon all still land. Phorion's advice is to treat any install of 2.1.313 as an incident regardless: review fleets for the extension, engage incident response, and remove the persistence rather than relying on the macOS bug. The writeup says Cursor has removed the release from its marketplace and that version 2.1.313 was also pulled from the NPM and VS Code registries; as with the earlier analysis, the extent of exposure beyond Cursor's marketplace is contested between researchers, and this writeup does not settle how the build was uploaded in the first place. (read more).

CVE-2026-98432: a use-after-free risk in the Linux kernel's TCP stack, with patch-validation discussion - a reminder that the infrastructure agents run on keeps its own vulnerability calendar. (read more ⚠).

A security writeup documents a supply-chain compromise: version 2.1.313 of the Claude Code extension published to the Cursor marketplace on October 29 was trojanized. The artifact looks identical to the legitimate extension - same bundled official binary - except for a 66-line malicious loader prepended to extension.js. Because the code sits at module load, the user does not even need to start a Claude conversation: the extension activating after VS Code startup is enough. The loader adds an attacker-controlled key to the user's SSH configuration, tries to enable the local SSH service, opens a reverse tunnel to 134.209.82.225, installs platform-specific persistence, and beacons host reconnaissance over unencrypted HTTP. Cursor's own security notice confirms the malicious build for its marketplace only - live there for about eleven hours on October 29 and reaching at most 5,000 users - says the version was not developed by Anthropic, and reports no evidence that other versions or the official distribution were affected. The writeup itself asserts the NPM package, the OpenVSX extension and the Microsoft VS Code extension are clean, but other researchers report the same build on Open VSX, so the scope outside Cursor's marketplace is not settled. The author also notes the analyzed directory's provenance is not established, so the findings prove this artifact is malicious without by themselves showing how it reached the marketplace. The economics seminar

A formal model of why the individual agent is the wrong economic unit: organizations, not people, are what AI has to outproduce.

This essay, drawn from the paper 'Organizing Intelligence', argues that the individual AI agent is the wrong economic object. Benchmarks measure single agents solving problems in isolation, but economic transformation is an equilibrium outcome: organizations assemble people with complementary strengths into teams that can outproduce any solo worker - which is why organizations have been called a form of superintelligence. A model can beat every person one-on-one and still lose to a well-structured team, which helps explain the disconnect between milestone-clearing frontier models and an economy that, on the surface, has barely changed. The authors instead define thresholds of economic capability - 'minimal AGI' among them - as functions of how they transform the economy, then track market structure, employment and wages across capability regimes. Standard economic models, they argue, miss the transformation because they still model machine intelligence as a better tool in a worker's hands or a machine swapped in for a person, rather than as a change in how coordination itself is produced. Plumbing for the agent economy

Natural lets agents choose their own payment rail at runtime - ACH, wire or realtime - with the operator's limits still in force.

Natural brings Direct to general availability, giving agents a runtime choice of payment rail: ACH, wire, or realtime payments over RTP and FedNow, with mailed paper checks and international wire promised next. The argument is that agents making on-the-spot decisions cannot know in advance who they will need to pay - the counterparty's rail, due date and banking details surface at runtime - so the financial primitives have to be selectable programmatically, from the same Natural wallet an agent already uses for instant payments, requests, issued cards and checkout acceptance. The operator keeps the reins: the controls and limits configured in Natural apply regardless of which rail the agent picks. The post walks through when each rail makes sense - ACH for payroll, invoices and rent with predictable next-day batch settlement, versus wires and realtime rails for immediacy. (read more).

Research notes

An escape-room primer explains why RL environments are the currency of post-training, and an eight-agent experiment shows swarm leadership emerging from model choice and prompt order.

A widely shared primer uses an escape room to explain reinforcement learning environments, a theme the author says was everywhere at this year's ICML. The mapping: the room is the environment with its objects, rules and feedback; the flashlight, box and keypad are the tools; escaping is the task; and the binary escaped-or-not result after an hour is the verifier. Swap the human for an AI agent and you have an RL environment - a clean way to see why verifiable, well-instrumented tasks have become the bottleneck and the currency of post-training. (read more).

Raindrop ran an experiment on leadership emergence in agent swarms: eight agents drawn from four models - Claude Sonnet 5.5, GPT-6.1 Sol, Gemini 3.1 Pro and Kimi K3 - worked as peers with equal permissions to resolve four simulated outages at a fictional online store. Many agents issued instructions, but only a few actually changed other agents' behavior - the emergent 'leaders'. Two factors predicted leadership potential: the agent's underlying model, and the order in which the agent's name happened to be listed in the prompt (names were rotated across models to control for bias). The takeaway for anyone assembling multi-agent systems: seemingly minor configuration details - which models you mix and how you list them - shape coordination outcomes as much as stated roles do. The discourse

Essays argue the real question for SREs and PMs is deskilling, not replacement, while a satirical open letter lets the AI industry state its own position on creative work a little too plainly.

A SigNoz newsletter essay asks a sharper question than the usual AI-and-jobs debate: not whether AI replaces SREs, but whether it quietly deskills them. If AI handles 95% of incident response, do engineers get worse at the 5% that actually matters - the novel outages? The piece anchors the concern in a 1983 research paper on automation that it calls eerily prescient, framing deskilling as a known failure mode of automation rather than a new AI anxiety. The two popular prophecies it rejects: that SRE is the future of all software engineering (humans keep the systems alive while AI writes the code), and that AI devours every tech job including SRE. Neither, the author argues, helps an SRE planning their Tuesday in 2027; the useful work is watching whether capability erosion is already happening and whether anyone notices before the next novel outage. (read more).

An essay argues that product managers should worry about AI at least as much as developers. The analogy: generative AI is to developers what Instagram was to professional photographers - 90% lost their moat to teenagers with phones, while the remaining 10% became more valuable because their talent could not be copied. 'Code spitters are cooked,' the author concedes, but architects are safer: reconciling needs with security, compliance, technical constraints and budget requires private data and interpersonal work that resists automation. The PM-specific threat: when code is cheap, the developer prompting a feature has time left over to build product intuition - understanding the customer pain point and why a feature should exist at all. If the same person can code and reason about the product, the PM's separate role compresses. (read more).

PostgreSQL 19 is running behind schedule - November at the earliest, missing the usual September-October window - and developer Robert Haas says AI is at fault, Phoronix reports. The project has been flooded with bug reports filed by AI/LLM agents. The workbench

An inference server scores one document against many questions in a single pass, ~25 lines of SQL compile to a FlashAttention kernel, and agents learn to play Pictionary in public.

spinf-serve is an open-source (Apache 2.0) inference server for bulk scoring and decisions rather than chat: it reads a piece of content once and answers many questions about it in the same forward pass, each answer a probability over provided options instead of generated text. It runs on a single 24GB NVIDIA GPU and exposes an OpenAI-compatible API. The motivation is workload shape: the team built it for a daily market index read from millions of news articles, each asked dozens of narrow calibrated questions - a job where a chat-oriented server re-reads content per question and generates token by token, making it slow and expensive. spinf-serve lays every question out as a branch of one read and packs many contents into a single pass. Any open instruction model works as a decision model this way; it ships for Linux on Ada, Hopper or Blackwell GPUs with fp8 tensor cores. (read more).

Sketch Stadium is a Show HN demo where AI agents play Pictionary: connect your own agent or watch a live game. Agents subscribe to game events and take turns drawing or guessing; easy clues score 1 point, medium 2, hard 3. The author built it as a proof-of-concept for sending push notifications to AI agents and shipped it after finding the agent games compelling to watch. A Show HN demo automatically derives a FlashAttention kernel from about 25 lines of SQL expressing vanilla attention.
