The bubble question

Whether the spending is a bubble or a one-off build-out.

A blogger argues the AI bubble may not exist. He grants that AI companies have committed to at least $3 trillion and spent an estimated $1.9 trillion, around $5 trillion in total, and that opaque financing vehicles make true costs hard to see, which he calls the strongest point for the bubble view. But he says spending need not continue: most of it is one-off data center build-out, not regular operating cost, so it should fall once the buildings are up, and AI is otherwise cheap to run. His claim is that the 'any day now' pop is taken for granted online, while there is a realistic chance that growth is justified with more room left. Only the first part of the post was readable, so the rest of his case is not covered. (read more).

Teaching the agent era

What engineers should learn when agents do the homework.

A Latent Space episode for the AI Engineer channel's one million subscribers features Mihail Eric, who teaches Stanford's CS146S and leads AI at Monaco. In the second run of the course, with coding agents able to finish last year's homework in one prompt, he added open-source maintainers: students learn an unfamiliar repo, propose a change and explain the patch to the person who might merge it. The conversation covers what junior engineers need to learn now, a tour of the ten-week syllabus, and which lessons survived at Monaco, which built its own agent workspaces, bought code review tools and gave an on-call agent access to Datadog and GitHub. Show notes link the syllabus, building a coding agent from scratch, and essays on code review and background agents. (read more).

The same Latent Space special, in a second post: the AI Engineer YouTube channel passed one million subscribers, and the host asks Mihail Eric what a software engineer should learn now. Eric teaches The Modern Software Developer at Stanford and leads AI at Monaco, where colleagues use coding agents to ship software and investigate outages. The post is also a preview of AIE Code in San Francisco. The first CS146S had nine assignments and a capstone, including running an AI code reviewer on a repo. By the next run students could one-shot many of them, and every sophomore and junior he surveyed already used an agent. So part of the homework is now a contribution to an open-source project, reviewed by its maintainer. The host's point: an agent can build a feature in an afternoon, but you still must learn whether the maintainer wants it and what it might break. (read more).

Simon Willison comments that educators now must change how they teach and assess, yet it is unclear what works with AI tools, and results take 3 to 6 years to see because they only show when a cohort graduates. Students effectively become guinea pigs for untested methods. (read more).

The workbench

Hands-on benchmarks.

Simon Willison, curious on a dog walk, asked Claude (Opus 5.5) to compare writing a SQLite parse_number() function, which strips commas, $, £ and % and handles a leading minus, as a C extension versus Rust. The binaries differ a lot: the Rust extension was 321 KB with rusqlite and 298 KB with sqlite-loadable-rs, against 14 KB for C. Yet the Rust version ran faster. He then asked for a C version that matches or beats Rust. Net cost per row over 2 million rows on mixed data was 67 ns for the first C, 19 ns for the new C, 46 ns for rusqlite and 41 ns for sqlite-loadable. On integers only: 25, 16, 36 and 32 ns. On decimals only: 106, 18, 55 and 47 ns. He had the model write the work up as a research report in the style of his simonw/research repository. (read more).

Simon Willison says most changes to his projects now arrive as pull requests opened by Claude Code or Codex, and agents write PR descriptions that are accurate but so thorough they read like slop. His reaction is to skip them, even when he is the one driving the agent. He wants a short human-approved introduction that says what the PR is for and whether it deserves attention. His low-effort fix is the HTML details and summary elements, which GitHub Markdown supports. The human writes a short visible summary and the agent's long description sits collapsed underneath, so readers choose how deep to go. (read more).

Simon Willison says a Hacker News comment pushed him to try Three.js-free 3D. He had Claude Opus 5.5 build a nudibranch-themed Faberge egg in Three.js (77 KB), then port it to vanilla JS and WebGL (98 KB). The two differ and Claude explained why in a shared transcript. He finds Three.js code easier to read but rarely reads the code. (read more).

OpenRouter has rebuilt its Auto Router and added an Auto Code router for coding tools. It says the new router beats the old one by up to 4x on benchmarks and picks a model 3x faster at p90 (0.65s against 1.96s). Instead of the earlier coarse signals like task type, it weighs eleven factors per request together with live pricing, provider health and cache status, within whatever governance limits the user sets, such as zero data retention or allowed models. Auto Code is tuned for coding with a higher tier of coding models. The company claims it scores in line with Claude Opus 5.5 across five benchmarks at 74% lower cost per task. It also says it moved back from favoring the cheapest models, which had made the old router drift downward. These are vendor claims. (read more).

Flide is a GitHub project that serves 'Jev-style' decision models through an API and claims up to 9.5 times faster inference than vLLM and SGLang by forking model state exactly, with answers matching those the model gives a question alone. The README shows installing it with pip and serving a small model. (read more).

Samir Sarwar's repository teaches LLM inference from first principles by building a small engine in C++ and CUDA. The series follows what happens between a prompt and a generated token: loading weights, then running each transformer part on the GPU. Parts cover prefill, decode and the KV cache, then static and continuous batching with a paged cache and online-softmax decode attention, using a Llama 3.2 1B path. The author says the 80+ pages of handwritten notes and diagrams were written without AI. The engine keeps a fixed 2,048-token context and a KV pool of 128 MiB by default. Admission reserves room for each request's maximum length so generation cannot deadlock, which avoids preemption but can limit concurrency when output budgets are large. (read more).

Uniform is a preview-stage UI library that replaces native text, layout and rendering with its own core written in C, compiled to WASM for the web and to native code elsewhere. A full web app using it is under 280 KB compressed. It renders through Metal on iOS and macOS and through GPU APIs in the browser, aiming for pixel-exact layout and consistent behavior across platforms. It offers a JavaScript API with no build step for fast iteration and a C API for more speed, and compiles from source, shaders included, in under a second. The README says it was written by hand with no AI involvement. The API may still change and not every feature is done. (read more).

Ginux is described as a new kernel that runs a Linux userspace, built through human-directed AI engineering. (read more ⚠).

HaCI is a GitHub project for edge detection in RGB images using a compact, fully distributed algorithm. It compares each pixel with its eight neighbors, pools responses by orientation, and uses contour facilitation and suppression in several stages. It is linked to a Zenodo paper. (read more).

Recalc is an open-source spreadsheet where each cell can be a Claude Code or Codex terminal. Agents fill cells in real time, and you can open any cell as a terminal and steer it by prompting or editing the cells. It runs locally on macOS, with Linux experimental. (read more).

STE80 Humanizer is a GitHub tool that tries to remove an 'AI voice' from text by rewriting it 80% of the way to the ASD-STE100 simplified-English standard, with before and after examples. (read more).

Code, licenses and security

Open source and security adapt to AI.

On The Verge's Decoder podcast, Nilay Patel talks with Alex Stamos, chief security officer at Cognition, about how AI is changing cybersecurity. Stamos argues the multibillion-dollar security industry as it existed is overdue for disruption. Criminal groups and state actors such as Russia and North Korea use AI to find and exploit vulnerabilities at the same time, which gives the moment a frontier feel like the 1990s. He is not a long-run doomer but expects a 'dark age' while defenders adapt. The conversation also covers AI-assisted red teaming, weaknesses in legacy codebases and how AI misinformation and slop might be handled on social networks. The page shown was the episode introduction, so the detail comes from the host's summary. (read more).

Terence Eden cut bot traffic to his hobby site OpenBenches by over 80% with a simple trap. The site had sent 2.5 TB in a month, mostly AI crawlers pulling data and images. He adds a honeypot directory forbidden in robots.txt; any visitor that requests it is a bot ignoring the rules, and a small PHP page writes its IP into a blocked list in .htaccess, which then returns a 402 'Payment Required' message. The post gives the code and warns it may block innocent visitors. (read more).

Asahi Linux, the project that made Linux run on Apple Silicon Macs, is moving all its repositories from the permissive MIT license to GPL version 2 or later. It says people have lifted unreleased feature code from developers' personal forks, or had AI rewrite it to hide where it came from, in order to replace the project and profit from it. MIT explicitly allows reuse and has no protection against bad-faith actors, so the team chose strong copyleft only. It Foss, which reports the change, explains 'code laundering': passing someone's code through a rewrite so it can be used without credit or license obligations. LLMs make that cheaper than the old manual renaming. Critics on social media object that relicensing may happen without every earlier contributor agreeing, and Asahi did not say how past contributions will be handled or name anyone it accuses. (read more).

Self-improvement and the upside

Data and local inference

What labs buy, and running big models on small machines.

Latent Space's first deep dive with an AI data company features Handshake AI, whose training-data business went from launch to $1 billion in gross annualized revenue in about a year. The episode asks what frontier labs are buying at that scale and shows live demos of the reinforcement learning environments Handshake builds. In bio, the VIALS benchmark tests reading scientific images such as tumor slides. The point is where models still trail humans. (read more).

EE Times reports DeepX claims inference of models up to 100B parameters at under 5 W on its second-generation chip. (read more ⚠).

A developer ran gpt-oss-120b and Qwen3.5-122B-A10B on a 32 GB M1 Max with a hard 16 GiB process-memory budget. The prototype keeps most mixture-of-experts weights on the SSD and brings in only what is needed. Memory is limited in practice and checked against macOS counters, not just set in config. On gpt-oss-120b it averaged 7.84 tokens/s over eight prompts against 5.78 for another engine, about 36% faster, with the gap growing when other processes used memory. Weights were checked byte for byte. The engine code is not released, so results are unreproduced. (read more).
