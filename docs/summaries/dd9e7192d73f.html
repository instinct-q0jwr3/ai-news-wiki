Nvidia RTX Spark encrypted firmware slows inference speed to 35% on Linux

type: news-summary · created: 2026-11-04 · updated: 2026-11-07 · confidence: high

Summary

A MindStudio write-up asks whether Linux is viable on Nvidia's new RTX Spark laptops, which are sold with Windows on ARM and up to 128GB unified memory for local AI work. Linux installs and runs with GPU acceleration through Nvidia's open kernel driver, but on wall power the GPU is locked at about 780 MHz instead of 2 GHz-plus on Windows. That cuts a 120-billion-parameter model from about 65 tokens per second to about 14, which the author ties to power-management firmware Linux cannot read.

The install was not simple on an MSI Prestige: Omarchy gave a flickering display, Debian lacked drivers and Wi-Fi, and returning to Omarchy, which bundles Nvidia's open driver, worked. Linux first saw only 28GB of 128GB because firmware reserves 96GB for the GPU, changeable only from Windows. Lowering that reservation freed 120GB, after which 4K at 120Hz, audio, touchpad and CUDA worked.

The takeaway for AI developers: usable, but you will lose about two-thirds of inference speed on Linux until the firmware issue is solved.

Highlights

  • RTX Spark laptops ship with Windows on ARM; Linux boots with GPU acceleration via Nvidia's open driver
  • On wall power the GPU clocks ~780 MHz vs 2 GHz+ on Windows; 65 to ~14 tokens/sec on a 120B model
  • Install needed Omarchy, a USB Ethernet adapter and a Windows-side memory reservation change
  • Fixing the 96GB GPU reservation gave Linux 120GB; the clock lock is tied to unreadable power firmware
