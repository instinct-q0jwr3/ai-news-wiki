Route and orchestrate models with GitHub Copilot Fusion

type: news-summary · created: 2026-10-29 · updated: 2026-10-30 · confidence: high

Summary

GitHub Copilot Fusion is now generally available, merging two earlier experiments - Project HydraFusion's multi-model orchestration and Copilot's auto model selection - into a single option in the model picker. Choosing Fusion means choosing a system, not a model: for each prompt it routes and orchestrates across models, balancing performance against cost. GitHub says Fusion Max scores 60 on the Artificial Analysis Coding Agent Index, within two points of Claude Code with Opus 5.5 Max, while using about half the average API cost per task, about half as many tokens and roughly 40 percent less time.

The enterprise pitch is spend hygiene: AT&T's Hari Pokhrel describes developers picking an overpowered model for one task and forgetting to switch back, with Fusion eliminating that friction and its decisions improving over time. Research-preview participants who enabled auto, HydraFusion or HydraFusion Max are transitioned automatically to the corresponding Fusion effort levels.

Highlights

  • Copilot Fusion GA: one picker option that routes and orchestrates across models
  • Merges HydraFusion orchestration with auto model selection
  • Fusion Max: 60 on AA Coding Agent Index, two points behind Claude Code Opus 5.5 Max
  • ~half the API cost per task, ~half the tokens, ~40% less time than the leader
  • AT&T cites recovered token spend from developers over-provisioning models
  • Preview auto/HydraFusion selections migrate to Fusion effort levels automatically
