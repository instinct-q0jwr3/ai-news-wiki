AI Can Write the Code. Who Verifies It?

type: news-summary · created: 2026-10-17 · updated: 2026-10-29 · confidence: high

Summary

As developers increasingly ship code they did not write or fully review, this essay argues the bottleneck has moved from writing code to verifying it. It cites a 2026 Faros study of 22,000 developers across 4,000 teams: throughput rises with AI adoption, but bugs, rework, review load and incidents rise faster - 54% more bugs per developer, a fivefold increase in median PR review time, and over three times as many incidents per PR. The author stresses these are correlations, and a later Q3 report showed some effects easing while downstream verification and remediation costs kept piling up.

The proposed answer is automated software verification: at the speed AI generates diffs, no small team can meaningfully review them, so correctness has to be established by tooling rather than human reading alone.

Highlights

  • Faros 2026 study: 22,000 developers, 4,000 teams, two years of telemetry
  • High AI adoption correlates with 54% more bugs per developer
  • Median PR review time up roughly fivefold; incidents per PR up 3x
  • Author cautions these are correlations, not proof of cause
  • Argues human review cannot scale to AI-generated diffs
  • Proposes automated software verification as the path to keep speed without losing quality
