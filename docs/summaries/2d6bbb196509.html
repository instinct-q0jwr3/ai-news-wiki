Go-based Robotics Framework built around NATS.io

type: news-summary · created: 2026-09-20 · updated: 2026-09-23 · confidence: high

hacker-news

Summary

Gorai (pronounced 'go-ray') is a Go-based robotics framework that treats a robot as what it really is, a distributed system: every sensor and actuator becomes a named service on a NATS mesh, discovered at runtime instead of wired by hand. It ports cloud-systems discipline, service discovery, location transparency, health checks, fan-out and replay, to robots built from MCUs, SBCs and sensors.

Its capability model (NCP, the NATS Capability Protocol) exposes sensors as resources and actuators as tools, giving AI agents MCP-style capabilities natively over NATS with no MCP server in the path, while safety is enforced at the capability node, not the agent. A 'Composite Robot' can span a rover, drone, sensor mast and compute box as one logical robot. Deployment is a single static binary on a Raspberry Pi or Orange Pi, no containers or Kubernetes, with a workstation CLI for building, validating, and observing the live mesh.

Highlights

  • Every sensor and actuator is a named service on a NATS mesh, discovered at runtime, addressed by name.
  • NCP (NATS Capability Protocol): resources and tools for agents natively over NATS, no MCP server needed.
  • Safety is enforced at the capability node; AI execution is welcome but never trusted.
  • Composite Robot: one logical robot spanning rover, drone, sensor mast and compute box, degrading gracefully.
  • Deploys as one static Go binary on Raspberry Pi 5 or Orange Pi 5; no containers, K8s or external services.
  • The gorai CLI (kubectl + build wrapper) runs on the workstation, never on the robot; mesh commands debug live systems.
  • Action logs, state streams and replay are first-class platform concerns.
  • Docs include strategy, specs, hardware analysis and a 20-chapter book, indexed for both humans and AI agents.
