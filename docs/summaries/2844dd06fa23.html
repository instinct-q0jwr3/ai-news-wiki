The AI cost of JavaScript frameworks

type: news-summary · created: 2026-11-01 · updated: 2026-11-04 · confidence: high

Summary

Nolan Lawson is tired of vibes. Web development's framework choices, he argues, have always been justified post-hoc - devs liked typing JSX, then invented the benchmarks to match - and the agentic era has made it worse: frontends now get rewritten because some framework is 'better for agents', and nobody thought to ask the agents or measure anything. So he wrote a benchmark. The test app is a deliberately ordinary content site - a searchable, filterable list of Pokemon with types, moves and game data - spec'd once and handed to Opus 5.5 at high effort with the instruction to use the latest version of each framework, leaning on each tool's official MCP or skills to preempt complaints about training-data representation.

The methodology is careful about its own limits: one holotype of app, closer to Wikipedia than to Figma; no mandated architecture (SSR vs CSR left open), no CSS methodology dictated, no instruction to optimize performance - each agent ran in a sandbox, unaware it would be Lighthouse-tested on performance and accessibility but given the conformance suite. The framing question is the point of the piece: in a world where the DX argument no longer applies because agents type the code, what should actually drive framework choice - and the answer starts with finally having numbers instead of vibes.
