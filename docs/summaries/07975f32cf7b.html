AX – Google’s Open Agentic Orchestrator

type: news-summary · created: 2026-09-21 · updated: 2026-09-21 · confidence: high

hacker-news google agentic-systems

Summary

AX is Google's open-source orchestrator for AI agents, built around a blunt observation: agents are neither microservices nor batch jobs. They accumulate state, need strict isolation, call out to model APIs and tool servers, and can burn money in a loop if nobody is watching. AX wraps that reality in four small declarative primitives, Kubernetes-style: sandboxes with CPU and memory limits that are cheap to create, suspend and throw away; workspaces that wire up the Git repos, MCP servers and skills an agent needs before the task starts; network policies that lock traffic to an explicit allowlist of hosts and ports with credential injection; and centralized model, parameter and secret configuration that rotates keys or pins versions with one apply.

The usage model is kubectl for agents: a task.yaml defines Workspace and Task resources, ax apply creates them, ax watch follows phases, and ax ssh opens a shell into the running task to inspect or nudge it. Tasks can be suspended and resumed, state intact. Underneath, AX runs on Agent Substrate, a compute runtime designed for massive density and fast stateful actor lifecycles: every task is a lightweight actor, idle agents waiting on model or tool responses are checkpointed and brought back in under a second with zero cold-start delay, and the design target is billions of concurrent agent sessions per cluster.

Highlights

  • AX: Google's open-source agent orchestrator, declarative Kubernetes-style CRDs (Workspace, Task).
  • Premise: agents are neither microservices nor batch jobs; they hold state, need isolation, and can spend money unsupervised.
  • Four primitives: sandboxes with CPU/memory limits, workspace setup (Git repos, MCP servers, skills), network allowlists with credential injection, centralized model/secret config.
  • Workflow: ax apply -f task.yaml, ax watch, ax ssh into the running task, suspend/resume/delete.
  • Runs on Agent Substrate, a runtime for massive density and fast stateful actor lifecycles.
  • Idle agents are checkpointed and resumed in under a second with zero cold-start delay.
  • Design target: billions of concurrent agent sessions per cluster.
