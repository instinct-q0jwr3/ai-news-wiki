Cheaper LLM labelling

type: news-summary · created: 2026-09-23 · updated: 2026-09-26 · confidence: high

lobsters

Summary

A developer needed to label git commits as either 'maintenance' or 'new development' and found the obvious solution was a cheap, relatively capable LLM (GPT 5.6 Luna) prompted with careful category definitions: features, CLI flags and API endpoints count as new development, while bugfixes, performance, diagnostics, stability and security fixes count as maintenance.

After manually verifying the model matched their own label on every commit in a small test set, they rolled it out at scale, calling Simon Willison's llm CLI tool in a pipe from Perl with a retry loop. The piece is a practical case study in when LLM labelling is 'good enough': a small hand-checked validation set, a forced binary label, and a cheap model.

Highlights

  • Uses GPT 5.6 Luna to classify commits as 'maintenance' or 'new development'.
  • Prompt defines each category explicitly and forces a single label as output.
  • Validated on a small hand-checked set before scaling up.
  • Calls Simon Willison's llm CLI in a pipe from Perl with retries.
  • A case study in cheap-LLM labelling being good enough for personal tooling.
