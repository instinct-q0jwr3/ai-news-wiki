Why are good developers so wary of agentic development?

type: news-summary · created: 2026-10-29 · updated: 2026-10-29 · confidence: high

Summary

Thoughtworks CTO Rachel Laycock puzzled over why so many excellent developers - people who usually adopt new ways of working first, who invented or championed CI, pairing, automated testing and continuous delivery - hesitate to go all in on coding agents. The easy explanations (they love writing code, they fear for their jobs) never satisfied her. An open-space session during this September's Technology Radar preparation finally surfaced the deeper fear: good developers know that built is not the same as working in production.

Early coding agents made it effortless to produce code, including code nobody would want near production. Developers whose careers revolve around building the right thing and building it right - software that can still be changed next year and does not fall over at 3am - read agent output through that lens. The wariness, in her account, is not nostalgia but scar tissue: the practices these developers invented exist precisely because writing code was never the hard part.

Highlights

  • Early agents produce code nobody would want near production, effortlessly
