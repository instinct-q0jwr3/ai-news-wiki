What is Codemode

type: news-summary · created: 2026-10-06 · updated: 2026-10-14 · confidence: high

Summary

Armin Ronacher explains Codemode, the MCP support added in Pi 1.0 - a seeming reversal of his earlier advice to skip MCP servers and just use scripts ('Code Is All You Need'). His reasoning: harness-provided tools become token structures the model is trained to call, and leaning on CLI/bash works well because composition is easy and the model already learned filesystem semantics - after 'echo foo > /tmp/test.txt', the model knows that file now exists.

But bash hits a wall: it can only compose runnable programs, and some capabilities must be native harness tools - read or view_image, because the image payload has to enter the model's protocol, and sub-agents, because spawning and orchestrating them through CLI shims and Unix sockets is crude. Codemode is his resolution: code-first where possible, native tools where the code physically cannot reach.

Highlights

  • Pi 1.0 adds MCP support via Codemode, updating Ronacher's earlier 'just use scripts' stance.
  • Bash composition works because models learned filesystem semantics in training.
  • Bash's limit: it composes only programs, not native LLM capabilities.
  • view_image and sub-agent orchestration must be harness tools - payloads live in the model protocol.
  • Codemode = code-first composition plus native tools where code cannot reach.
