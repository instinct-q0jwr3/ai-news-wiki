Why Are Coding Agents So Dumb?

type: news-summary · created: 2026-10-09 · updated: 2026-10-29 · confidence: high

Summary

After an early-2025 honeymoon with coding agents, this author concluded the agents - not the models - stayed bad: they hang until restarted, declare tasks finished when work has barely begun, and manage tasks atrociously. His taxonomy: the model (GPT Astra, Claude Sonnet, GLM-5.3) is the brain that generates text; the agent (Claude Code, Codex) is the body that glues that text to commands and files.

His running example: adding passphrase-protected links to his open-source file-upload app, about 1.5k lines of new code. OpenCode broke the feature into 10 subtasks - then executed the embarrassingly parallel subtasks one at a time. Why, he asks, is a computer with many cores and millisecond context-switching serializing work a human would trivially parallelize? The essay is a catalog of how agent tooling lags the models it wraps.

Highlights

  • Thesis: models improved dramatically while coding agents stayed bad - the agent is the bottleneck.
  • Model = brain (generates text); agent = body (glues text to commands and files).
  • Symptoms: hangs requiring restarts, premature 'done' declarations, primitive task management.
  • Example: OpenCode split a 1.5k-line feature into 10 parallel subtasks, then ran them serially.
  • Core frustration: computers are built for parallelism, yet agents work one task at a time.
