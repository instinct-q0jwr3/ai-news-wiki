Cloudflare says it deployed default WAF mitigations for all free and paid tier customers to combat two PHP flaws, roughly nine hours ahead of public disclosure

type: news-summary · created: 2026-10-21 · updated: 2026-10-29 · confidence: high

Summary

Cloudflare describes its role in the coordinated php2shell disclosure (CVE-2026-109618 and CVE-2026-109619, by Calif.io, Wiz, OpenAI, and Quarkslab): it developed WAF protections in early October and deployed them about nine hours ahead of the 21 October public disclosure, so free and paid WAF customers were protected by default from 3:02 UTC. The vulnerability leaked before the official release and Cloudflare observed live attack traffic, including attackers mutating payloads to evade the rules. Because request data alone cannot always distinguish an exploit from legitimate traffic, Cloudflare built full transaction detection, a new WAF capability combining request and response signals in the same HTTP transaction, with php2shell as its first managed detection. Customers are still told to patch; the WAF is defense-in-depth.

Highlights

  • WAF mitigations deployed ~9 hours before public disclosure
  • Default-on protection for all free and paid Cloudflare WAF customers from 21 Oct 3:02 UTC
  • php2shell = CVE-2026-109618/109619, disclosed by Calif.io, Wiz, OpenAI, Quarkslab
  • Vulnerability leaked early; live attack traffic and payload mutation observed
  • New capability: full transaction detection combining request and response signals
  • Patching still required; WAF is an added layer
