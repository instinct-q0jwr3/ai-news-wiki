Better Models: Worse Tools

type: news-summary · created: 2026-09-26 · updated: 2026-09-26 · confidence: high

armin-ronacher openai anthropic agentic-systems external-evaluation small-specialist-models ai-coding-agents labor-displacement

Summary

A strange bug in the Pi harness sent Armin Ronacher down a rabbit hole: newer Claude models - Opus 4.8 and Sonnet 5, not some small variant - sometimes call the edit tool with invented extra fields in the nested edits array. The edit itself is usually correct, but the arguments do not match the schema, so Pi rejects the call and the model retries. The odd part is that this is getting worse with newer Anthropic models: older siblings do not show it, meaning the SOTA models are worse at this specific tool schema than their predecessors.

The post explains how tool calling actually works under the hood: no magic, just in-band signalling where the server folds tools into the prompt with special marker tokens and the model emits something the client interprets as a call. For Anthropic models an 'ANTML' format leaks at times - not really XML, just something convenient to tokenize and train on - where string parameters appear inline but arrays of objects are JSON-serialized, a mixed convention he suspects is close to how it works. Without grammar-aware constrained decoding, the model merely follows a learned convention, and in the failing cases it invents a zoo of trailing keys: requireUnique, oldText2, newText2, type, id, kind, matchCase, forceMatchCount and more. He deliberately did not test Fable, unsure whether Anthropic's classifiers might silently downgrade him to Opus.
