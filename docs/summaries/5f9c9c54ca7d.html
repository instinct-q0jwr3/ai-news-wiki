parse_number() as a SQLite extension: C vs Rust

type: news-summary · created: 2026-11-09 · updated: 2026-11-09 · confidence: high

Summary

Simon Willison, curious on a dog walk, asked Claude (Opus 5.5) to compare writing a SQLite parse_number() function, which strips commas, $, £ and % and handles a leading minus, as a C extension versus Rust. The binaries differ a lot: the Rust extension was 321 KB with rusqlite and 298 KB with sqlite-loadable-rs, against 14 KB for C. Yet the Rust version ran faster.

He then asked for a C version that matches or beats Rust. Net cost per row over 2 million rows on mixed data was 67 ns for the first C, 19 ns for the new C, 46 ns for rusqlite and 41 ns for sqlite-loadable. On integers only: 25, 16, 36 and 32 ns. On decimals only: 106, 18, 55 and 47 ns. He had the model write the work up as a research report in the style of his simonw/research repository.

Highlights

  • parse_number() strips separators and currency symbols, returns NULL on failure.
  • Rust extensions were 298-321 KB; C was 14 KB.
  • First C was slower than Rust; a rewritten C was fastest in all three tests.
  • Mixed data per row: 19 ns new C versus 41-46 ns Rust.
  • The model also produced the write-up as a research report.
