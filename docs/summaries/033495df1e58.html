LLMs are terrible at designing AI systems

type: news-summary · created: 2026-11-08 · updated: 2026-11-08 · confidence: high

Summary

Sean Goedecke argues that LLMs are poor at designing software that itself uses LLMs. They write ordinary programs comfortably, but given an AI-shaped problem they tend to get it wrong. His example is a vibe-coded memory tool meant to flag contradictory memories: an LLM could simply scan for contradictions in a batch or pairwise, yet when asked for the state of the art, the agent built a complex symbolic system that converted memories into logical atoms for a solver.

That approach could not work, since no analytic method decides whether two natural-language sentences express the same proposition. The model knew this, and explained it was a 130-year-old unsolved problem once the user pushed, yet it iterated on the dead end for weeks. He has seen the same while building Autodeck, where agents kept trying to categorize cards with regex. His framing is that good design depends on the requirements you do not have, and models do not weigh those well.

Highlights

  • LLMs are weak at designing systems that use LLMs.
  • Example: a contradiction-flagging memory tool where an LLM scan was the easy answer but the agent built a symbolic solver.
  • The model knew the problem was unsolved yet spent weeks on it.
  • Same pattern with regex categorization in his Autodeck project.
  • Good design depends on identifying requirements you can drop.
