# Astra for Coding: Why Are We Doing This Again?

_type: news-summary · created: 2026-09-26 · updated: 2026-09-26 · confidence: high_

## Summary

Armin Ronacher tried to celebrate GPT-6 Astra's release by running a 'software factory' over a weekend: a setup where the model managed its own context, kept records in an agent-notes folder and spun off subagents, all pointed at one goal - a Python with virtual threads and lexical scoping. After burning what appeared to be around 4 billion tokens over 35 hours, the factory had produced nothing of value and taught him nothing about running a better one, though it left plenty of code and prompts to study.

He frames the experience as Neijuan - involution: ever more effort and competition without improving output. Astra is genuinely impressive at computer use, images and relentless long-horizon pursuit, and it reverse-engineered his robot vacuum in ways he found remarkable. But for actual software engineering he suspects something is going wrong in training: the model is heavily rewarded for succeeding on long-horizon tasks and apparently punished very little for bad code. Tellingly, where Codex increasingly leans on plain bash, Astra excessively resorts to on-the-fly Python - in the factory logs he found subagents doing manual string manipulation with Python instead of using the patch tool.
