# Keeping Large MoE Training Within Fixed GPU Memory

_type: news-summary · created: 2026-09-23 · updated: 2026-09-24 · confidence: high_

`tldr-ai` `compute-buildout`

## Summary

A systems paper tackles MoE training at long context or large batch: failure happens as soon as any single component's peak allocation exceeds device memory, so the target is bounding every peak at once rather than the average footprint. Four peaks escape common parallelism plans - expert dispatch (routing matrix), vocabulary projection (tokens x vocabulary), gradient checkpoint boundaries (depth x sequence length), and optimizer state (parameter count) - and which one blows up first changes with model, context length and device count.

The authors bound all four with schedules whose GPU working set is fixed at launch: PipelinedLLEP caps the tokens each source contributes to a dispatch chunk, Ring-DTP circulates activations or weight shards around a ring at the vocabulary projection and folds logit blocks into an online log-sum-exp, Selective Checkpoint Offload keeps each boundary's one long-lived tensor in CPU memory, and OffloadStreamAdamW streams the serial CPU Adam update.

## Highlights

- Goal: fixed GPU working set for MoE training at long context or large batch.
- Four unbounded peaks identified: dispatch, vocabulary projection, checkpoint boundaries, optimizer state.
- PipelinedLLEP caps per-source tokens in expert dispatch chunks.
- Ring-DTP circulates shards at the vocabulary projection with online log-sum-exp.
- SCO offloads checkpoint boundary tensors to CPU; OffloadStreamAdamW streams the CPU Adam update.
