# Control the ideas, not the code

_type: news-summary · created: 2026-09-26 · updated: 2026-09-26 · confidence: high_

`antirez` `openai` `deepseek` `agentic-systems` `external-evaluation` `small-specialist-models` `compute-buildout` `ai-policy-regulation`

## Summary

antirez's manifesto for programming's next phase: if you control the ideas of your software, reading the code is suboptimal and often pointless. His reasons: nobody can review 5k generated lines a day; LLMs write locally optimal code but are weaker on big ideas, so prompt the design you want and evaluate the model of the system instead; and every hour spent reading code is an hour not spent on direction, features and QA.

He's candid about the tension: he still reviews Redis code out of respect for its users, while believing it's mostly pointless now that models like Fable and GPT 5.6 Sol spot more races than he will - what he'd rather produce is a DESIGN.md where each data structure is described in human language. His framing borrows the Mythical Man Month and his own DwarfStar inference work (subtle bugs in hand-written GPU kernels everywhere) to argue the pre-AI software world was already rotten with slop. His one open doubt: young programmers who can't yet build a mental model - for them he suspects writing small interpreters and databases beats reviewing webshit.

## Highlights

- 'Control the ideas, not the code': reviewing generated code is a poor use of the day
- LLMs: locally optimal code, weaker big ideas - steer design, not lines
