# How the Claude Code team thinks about verification

_type: news-summary · created: 2026-11-17 · updated: 2026-11-23 · confidence: high_

`tldr-ai` `anthropic` `agentic-systems` `ai-coding-agents`

## Summary

The Claude Code team describes verification loops built around end-to-end, property-based and differential tests. Its argument is that agent-written code needs evidence from real user flows and independent comparisons, not simply another confident review of the same implementation.

The article also warns that verifiers can be flaky, slow or share the implementation’s mistaken assumptions. Reported internal success gains are bounded experiments, not a promise of a fixed improvement on every codebase. Generated tests still need checks that they fail for the right reasons.

## Highlights

- Real user flows test integrated behavior
- Property tests search for counterexamples
- Differential tests compare implementations
- Verifier quality needs its own evaluation
- Internal gains are not universal performance guarantees
