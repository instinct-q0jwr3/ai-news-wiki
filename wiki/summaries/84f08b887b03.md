# Memory is slow, Disk is fast

_type: news-summary · created: 2026-10-24 · updated: 2026-10-31 · confidence: high_

`lobsters`

## Summary

'Memory is slow, Disk is fast' argues that Big O notation lies by omission: an O(sqrt n) disk-based structure can beat an O(log n) one in practice when constants and I/O patterns favor it. The author built a disk-backed ordered structure whose directory blocks split as they grow - and discloses the corner case honestly: the top-level index grows with n, so on average once every couple hundred thousand inserts it memmoves about 1.4 MiB and rebuilds its count tree, which is noise next to drive I/O.

Had the author made the index recursive as planned - extents all the way up - the structure would officially be a B-tree variant with guaranteed O(log n); at current settings a second tier only kicks in around 8G nodes. The point stands: asymptotic classes mislead when the machine's real costs are block transfers and cache misses, and a well-shaped disk layout can make the 'slow' medium look fast. Source code is published.
