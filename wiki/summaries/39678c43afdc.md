# Periodic-Oriented Programming for FIRST Robotics

_type: news-summary · created: 2026-11-15 · updated: 2026-11-19 · confidence: high_

`lobsters`

## Summary

A long-time FIRST Robotics mentor proposes Periodic-Oriented Programming: keep robot behavior readable in a top-to-bottom periodic loop, with a small number of explicit subsystem boundaries rather than many command abstractions. Subsystem methods set desired state, while centralized periodic logic validates constraints and updates hardware consistently.

The argument is aimed at teaching and maintaining FRC robots, drawing on the author’s own experience. Its safety benefits depend on implementing those boundaries correctly; one function or fewer abstractions does not by itself prove a robot safe or make this the right structure for every application.

## Highlights

- Approach targets FIRST Robotics programs
- Periodic loop makes update order explicit
- Subsystems centralize hardware access
- High-level calls express desired state
- Benefits are practitioner claims, not universal guarantees
