# Show HN: Compile the same source for GPUs and CPUs

_type: news-summary · created: 2026-11-22 · updated: 2026-11-26 · confidence: high_

`hacker-news` `anthropic` `external-evaluation` `small-specialist-models` `compute-buildout` `ai-policy-regulation`

## Summary

xc is a hobby heterogeneous data-parallel language project: write an ordinary loop in xc or C and its compiler, xcc, runs it across every CPU core, on GPUs through Metal, CUDA, Vulkan or WebGPU, across multiple GPUs from different vendors, or on a GPU in another machine, keeping whichever run is fastest. The project says kernels are generated by xcc itself and carried inside the executable, so a build needs no GPU toolkit installed. The repository holds the compiler plus a GUI framework and tools, and its README describes contribution rules, a contributor licence agreement and a clean-start history after earlier check-ins mixed in private material.

The performance and portability claims are the project's own, with benchmarks the author says were measured on hardware the project bought; no figure was independently reproduced here, and results on one person's machines may not transfer to other GPUs or workloads. The multi-vendor and remote-GPU execution modes are described in the documentation, not demonstrated to this pass. The compiler was not built or run.

## Highlights

- One loop source runs on CPUs, GPUs, multi-vendor GPU sets or a remote GPU
- Kernels are generated by the compiler and embedded in the executable
- No GPU toolkit needed at build time, per the project
- Benchmarks are self-measured on project-owned hardware
- Documentation claims were read, not tested, in this pass
