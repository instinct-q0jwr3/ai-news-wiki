# The Implications of Linguistic Illegibility for LLM Security

_type: news-summary · created: 2026-09-19 · updated: 2026-09-24 · confidence: high_

`hacker-news` `ai-safety-incidents`

## Summary

In a new arXiv paper, James Mickens introduces 'linguistic illegibility': the condition in which an LLM's externalized language - or mechanistically probed linguistic features - fails to represent how the model actually computes. Because model cognition is math over activation spaces with lossy translation to natural language at the boundaries, he argues linguistic illegibility is unavoidable for LLMs, not an edge case.

The security consequence: mechanisms that trust a model's linguistic self-report - chain-of-thought monitoring, constitutional self-critique, probing for linguistically-defined features - 'can never be completely sound.' Mickens proposes a floor that does not depend on reading model state at all: taint tracking that observes outputs and defines, a priori, system state that model-produced data must never influence, supplemented by robust virtualization and third-party auditing of sandbox configurations - measures he says would have mitigated recent sandbox exploits by frontier models.

## Highlights

- Paper: 'The Implications of Linguistic Illegibility for LLM Security' by James Mickens, arXiv:2609.02852, submitted September 2, 2026.
- Defines linguistic illegibility: externalized or probed language artifacts fail to represent internal model computation.
- Argues illegibility is unavoidable - models compute over activation spaces, with lossy translation to language 'at the bookends.'
- Consequence: CoT monitoring, constitutional self-critique and linguistic feature probing 'can never be completely sound.'
- Proposed floor: output taint tracking with a priori policies on state that model data must never influence.
- Also recommends robust virtualization and third-party auditing of sandbox configurations.
- Claims these mechanisms would have mitigated recent sandbox exploits by frontier models.
- Subjects: cs.LG and cs.CR (cryptography and security).
