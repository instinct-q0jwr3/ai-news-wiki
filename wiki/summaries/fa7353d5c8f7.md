# If you don't run your own LLM proxy, how do you know whats going on?

_type: news-summary · created: 2026-10-19 · updated: 2026-10-20 · confidence: high_

`hacker-news`

## Summary

A rant-flavored engineering argument that anyone building seriously on LLM APIs should run their own LLM proxy rather than trusting provider dashboards. The author's core complaint is observability: the usage charts and analytics panels that frontier labs expose are marketing-grade visuals, not the per-request, time-series token and cost data an engineer needs to make decisions. OpenTelemetry export options exist but don't close the gap. The post lists a handful of additional reasons (beyond analytics) for interposing your own proxy, and argues the proxy should be self-hosted somewhere you control rather than another third-party service - the author has modified theirs for better insight, custom MCP server endpoints and extra features. The recommendation is deliberately vendor-neutral: pick any proxy, run it yourself, and shape it to your needs.

## Highlights

- Argument: without your own LLM proxy you lack real visibility into token usage and cost
- Provider analytics dashboards are dismissed as consumer-grade visuals, not engineering data
- Decisions about model usage require per-request time-series data labs don't expose well
- OpenTelemetry export from providers exists but the author finds it insufficient
- Proxy should be self-hosted, not another third-party middleman
- Author has extended their proxy with custom MCP endpoints and deeper insight features
- Deliberately recommends no specific proxy vendor - just that you run one yourself
