# AI coding has made CI a bottleneck, so we reworked ours to keep up

_type: news-summary · created: 2026-09-21 · updated: 2026-09-21 · confidence: high_

`hacker-news`

## Summary

Linear describes how it reworked its CI pipeline after AI coding agents turned continuous integration into a bottleneck: agents made shipping code exponentially faster, but every PR still has to pass CI, so infrastructure costs and feedback latency ballooned. Despite test suites almost quadrupling since the start of the year, the company cut PR wait time from over six minutes to just over five, and roughly halved runner time per test.

The gains came from four directions. Moving off GitHub Actions to third-party runners with faster CPUs, better storage and cache infrastructure made jobs 34% faster on average (tsc down 52%). Switching to tsgo, the native TypeScript compiler, cut the weekly median of the typecheck by 73%, moving the bottleneck off typechecking entirely. Linting and other pipeline stages got similar treatment, and the post notes the optimizations apply beyond TypeScript.

## Highlights

- Trigger: the CTO filed an issue titled 'CI costs are high' as agent-driven development outpaced validation.
- Result: PR wait time down from 6+ minutes to just over 5; runner time per test cut roughly in half, while test suites nearly quadrupled.
- Third-party runners vs GitHub Actions: jobs 34% faster on average, tsc workloads down 52%.
- tsgo (native TypeScript compiler) cut the weekly median tsc check by 73%.
- Framing: when AI accelerates authoring, CI capacity and latency become the limiting factor of the whole pipeline.
