# .md File is not a specification: Using formal analysis to find requirements gaps

_type: news-summary · created: 2026-10-09 · updated: 2026-10-10 · confidence: high_

`hacker-news`

## Summary

A FizzBee post argues that a markdown requirements file is not a specification. Using a booking example, it shows that requirements written in EARS notation can look well specified yet hide gaps: one requirement, that appointments fall within a stylist's schedule, is a property to hold across states, not an observable behavior one can test directly.

The author proposes formal analysis to find ambiguity, inconsistency and missing cases before giving requirements to an engineer or coding agent. The post is from a vendor of a formal-modeling tool.

## Highlights

- Markdown requirements are not a specification
- EARS notation can still hide untestable properties
- Example: appointments must lie inside stylist schedules
- Formal analysis finds gaps before agents build
- Vendor of a formal-modeling tool
