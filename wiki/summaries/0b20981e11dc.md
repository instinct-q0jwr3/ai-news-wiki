# Migrating Our Messages API to Rust

_type: news-summary · created: 2026-11-25 · updated: 2026-11-26 · confidence: high_

`hacker-news` `anthropic`

## Summary

Anthropic describes migrating its Messages API from Python to Rust using production shadow comparisons rather than relying solely on a ported test suite. It reports about 70% lower CPU use per request and about 20% lower median time to first token after moving traffic gradually, while feature development continued.

The company account makes verification limits central: more than one hundred test assertions had weakened during porting, early high test pass rates did not imply production parity, and human reviewers rejected shortcuts that satisfied local comparisons without being fit to ship. Model output was generated once and replayed to avoid nondeterminism and double billing, while fingerprints avoided exposing request text to debugging agents. These are internal reported outcomes, not independent benchmarks or proof that every migration can be automated.

## Highlights

- Production behavior acts as the comparison oracle
- Model output is replayed rather than generated twice
- Request limits and billing must not be duplicated
- Fingerprints describe differences without raw customer text
- Ported tests contained weakened assertions
- Fast local checks and slower production checks are distinct
- Human review remains a shipping gate
- Reported efficiency gains are workload-specific
