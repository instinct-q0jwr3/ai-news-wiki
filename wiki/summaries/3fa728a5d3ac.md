## Summary

Simon Willison highlights PostgreSQL 19’s described ability to wait for a replica to replay a specified write-ahead-log position before reading. His example separates a write on the primary from a later standby read and compares the pattern with MediaWiki’s existing replication handling.

This is a link-post explanation, not an independently checked release note or tested deployment. Waiting for a chosen position does not make every replica instantly current, and the optional timeout can return an error. No SQL or database upgrade was executed.

## Highlights

- Post discusses read-after-write consistency
- Application must retain the relevant log position
- Standby waits for replay rather than becoming instantly synchronous
- Timeout is a failure condition not a freshness guarantee
- MediaWiki comparison uses a different database implementation
- Release and code were not independently tested
