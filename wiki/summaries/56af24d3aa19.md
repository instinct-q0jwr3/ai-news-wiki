# Orchestrating Claude Code Agents: The Chief of Staff Pattern

_type: news-summary · created: 2026-09-20 · updated: 2026-09-24 · confidence: high_

`hacker-news` `anthropic` `agentic-systems` `ai-coding-agents`

## Summary

This post lays out a 'Chief of Staff' pattern for orchestrating Claude Code agents on long-horizon work: one long-lived coordinator session assigns work, verifies claims and maintains shared state, while short-lived executor sessions do the implementation, and a durable external board holds the truth. The diagnosis is that long autonomous runs fail less from coding ability than from ephemeral context and unreliable self-reports, and that adding more agents only multiplies the problem unless someone owns 'what is true'.

The verification discipline is the core contribution: a red gate first (the verifier must fail before work starts, otherwise nothing is proven), every claimed command re-run with exit codes deciding, diffs read hunk by hunk, and one work item per dispatch and commit. The mental model is Git's integration-manager workflow, and the stack is replaceable: Claude Code sessions, cmux for scriptable terminal workspaces, and Plan Desk, an MCP-exposed planning board, as the memory that outlives any context window.

## Highlights

- Pattern: one coordinator session plans and verifies; separate short-lived sessions implement; shared state lives outside any context window.
- Rule: the coordinator never writes implementation; the moment it codes, it stops verifying and the pattern collapses.
- Red gate first: run the verifier before starting; if it is already green, the work proves nothing and may already be done.
- Every claimed command is re-run; exit codes, not agent self-reports, decide what is true.
- Loop: pull next unblocked task, read its design doc, red gate, delegate, prove, observe the diff, gate the approval lane, ship one commit.
- Tooling: Claude Code sessions (isolated context windows), cmux for scriptable workspaces, Plan Desk as an MCP planning board.
- Skipping the durable board is cited as the main reason multi-agent setups 'do not survive the night'.
- Prior art named: orchestrator-worker and coordinator-implementor-verifier shapes, and Git's integration-manager workflow.
