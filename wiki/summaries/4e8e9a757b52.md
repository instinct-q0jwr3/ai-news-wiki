# WorkOS reports security breach

_type: news-summary · created: 2026-11-03 · updated: 2026-11-08 · confidence: high_

`hacker-news` `external-evaluation` `ai-safety-incidents`

## Summary

WorkOS notified customers of a security breach detected October 30, 2026 - and the notification names an unusual suspect: the attack 'was likely driven by ARTEX, an AI-assisted, autonomous penetration testing framework,' launched from IP addresses in Hong Kong and China. The intruder reached an internal API behind WorkOS's sales and marketing tools and pulled data from Salesforce and Snowflake instances: CRM records including names, emails, phone numbers and business addresses, plus support tickets and de-identified usage metrics.

The company says there is no evidence that application data or production WorkOS services were touched - the blast radius is CRM and customer-support data. CEO Michael Grinich showed up in the Hacker News thread to field questions directly.

If the attribution holds, this is a milestone incident: an autonomous AI pentest framework run as an offensive tool against an identity-infrastructure vendor - the agentic-attack scenario moving from conference talks into breach notifications. For defenders it compresses the timeline question the same way the Savannah audit did from the white-hat side: the same class of tooling now appears on both sides of the ledger.

## Highlights

- WorkOS breach notification: attacker accessed an internal API and pulled CRM/support data from Salesforce and Snowflake instances
- WorkOS says the attack was likely driven by ARTEX, an AI-assisted autonomous penetration testing framework, from IPs in Hong Kong and China
- No evidence application data or production services were accessed; CEO answered questions on HN
- If attribution holds: an autonomous AI pentest framework named in a real breach notification - agentic offense arriving in the wild
