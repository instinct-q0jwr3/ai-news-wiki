## Explicit loops and configurable endpoints

A robotics programming argument and a small Datasette release favor visible control boundaries.

A long-time FIRST Robotics mentor proposes Periodic-Oriented Programming: keep robot behavior readable in a top-to-bottom periodic loop, with a small number of explicit subsystem boundaries rather than many command abstractions. Subsystem methods set desired state, while centralized periodic logic validates constraints and updates hardware consistently. The argument is aimed at teaching and maintaining FRC robots, drawing on the author’s own experience. Its safety benefits depend on implementing those boundaries correctly; one function or fewer abstractions does not by itself prove a robot safe or make this the right structure for every application. ([read more](../summaries/39678c43afdc.md)).

Simon Willison announces OpenAI-compatible endpoint support in datasette-llm 0.1a11, the configuration layer used by other Datasette plugins. This lets a Datasette application select a locally or remotely hosted model through the same API-style interface. The example combines Datasette Agent with a local model server. Compatibility with the protocol is the key addition, not a claim that every model supports the same tools, performs equally well or keeps data local when pointed at a remote endpoint. ([read more](../summaries/6e370e2d53b1.md)).

## What a representation does not prove

Model geometry, licensing arguments and separate account configurations need precise boundaries.

Jakub Jankiewicz argues that AI-generated code should be released openly because models benefited from the open-source commons and because purely machine-generated work raises authorship questions. He distinguishes an ethical obligation to give back from differences in copyright treatment across jurisdictions. This is a licensing proposal, not a legal determination that every AI-assisted program is uncopyrightable or inherits the licenses of its training material. Mixed human and machine authorship complicates the position, and the essay’s preferred remedy is explicit open licensing or public-domain dedication. ([read more](../summaries/d5948adce70d.md)).

An exploratory Qwen3-1.7B visualization maps internal token representations across constructed conversations in several languages. The author records normalized final-token states and places datasets in one shared PCA frame so adding another language does not silently rotate the comparison axes. The initial English paths appear nearly planar in the three-dimensional projection, but that observation is explicitly about the projection, not the full 2,048-dimensional state space. The deliberately small sample and visualization choices limit any claim about universal model geometry or a model’s understanding. ([read more](../summaries/adbb4089b646.md)).

A social-post author describes using separate Claude Code configuration directories to keep personal and work accounts signed in on one Mac. The account identity, history and settings can then follow distinct launch commands rather than repeated sign-out and sign-in. The author emphasizes that separate configurations do not isolate filesystem access and shared links to rules remain shared files. This is one user’s tested setup, with limits noted for other authentication methods and operating systems, not an official guarantee of account or data isolation.
