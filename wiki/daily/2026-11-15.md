## Explicit loops and configurable endpoints

A robotics programming argument and a small Datasette release favor visible control boundaries.

A long-time FIRST Robotics mentor proposes Periodic-Oriented Programming: keep robot behavior readable in a top-to-bottom periodic loop, with a small number of explicit subsystem boundaries rather than many command abstractions. Subsystem methods set desired state, while centralized periodic logic validates constraints and updates hardware consistently. The argument is aimed at teaching and maintaining FRC robots, drawing on the author’s own experience. Its safety benefits depend on implementing those boundaries correctly; one function or fewer abstractions does not by itself prove a robot safe or make this the right structure for every application. ([read more](../summaries/39678c43afdc.md)).

Simon Willison announces OpenAI-compatible endpoint support in datasette-llm 0.1a11, the configuration layer used by other Datasette plugins. This lets a Datasette application select a locally or remotely hosted model through the same API-style interface. The example combines Datasette Agent with a local model server. Compatibility with the protocol is the key addition, not a claim that every model supports the same tools, performs equally well or keeps data local when pointed at a remote endpoint. ## What a representation does not prove

Model geometry, licensing arguments and separate account configurations need precise boundaries.

An exploratory Qwen3-1.7B visualization maps internal token representations across constructed conversations in several languages. The author records normalized final-token states and places datasets in one shared PCA frame so adding another language does not silently rotate the comparison axes. The initial English paths appear nearly planar in the three-dimensional projection, but that observation is explicitly about the projection, not the full 2,048-dimensional state space. The deliberately small sample and visualization choices limit any claim about universal model geometry or a model’s understanding. A later full-space check sharpens that warning: the displayed three directions preserve 17.6% of final-token variation, and even the best full-space plane captures 28.7%, with 28.4% on held-out topics. Refitting PCA on conversation averages rather than a vocabulary-heavy point set also changes the visible relationships. The geometry is sensitive to what the map is optimized to preserve. ([read more](../summaries/adbb4089b646.md)).

Jakub Jankiewicz argues that AI-generated code should be released openly because models benefited from the open-source commons and because purely machine-generated work raises authorship questions. He distinguishes an ethical obligation to give back from differences in copyright treatment across jurisdictions. This is a licensing proposal, not a legal determination that every AI-assisted program is uncopyrightable or inherits the licenses of its training material. Mixed human and machine authorship complicates the position, and the essay’s preferred remedy is explicit open licensing or public-domain dedication. ([read more](../summaries/d5948adce70d.md)).

A social-post author describes using separate Claude Code configuration directories to keep personal and work accounts signed in on one Mac. The account identity, history and settings can then follow distinct launch commands rather than repeated sign-out and sign-in. The author emphasizes that separate configurations do not isolate filesystem access and shared links to rules remain shared files. This is one user’s tested setup, with limits noted for other authentication methods and operating systems, not an official guarantee of account or data isolation. Niklas Roy describes building a working pendulum clock from drink cartons and simple household materials. A browser tool developed with Claude helped design and simulate the escapement, but physical prototypes exposed the limits of cardboard precision: a simpler, larger five-tooth wheel worked where the first design failed. The project shows AI-assisted tooling inside an iterative mechanical build rather than a model independently producing a finished clock. The five-tooth mechanism belongs to the proof of concept. The later hour-running clock uses a larger 15-tooth escape wheel, full hour and minute gearing, and another AI-assisted browser tool for gear stencils and assembly tools. It still runs fast: operating duration and timekeeping accuracy are separate results. ([read more](../summaries/0a11dd8f4cd1.md)).

db-branch is a self-hosted beta for giving tests, pull requests and coding agents disposable MySQL or PostgreSQL databases. It uses ZFS snapshots and copy-on-write clones so a branch can be created without first copying the entire underlying database; each branch runs a separate server on its own port. The project documents reset, checkpoint and restore operations alongside runtime and storage requirements. Its core is Apache-2.0, while authentication, audit, history and other modules are separately licensed. Fast branch creation is a project claim, not a measured guarantee of query performance, production isolation or protection for sensitive data copied into a base.
