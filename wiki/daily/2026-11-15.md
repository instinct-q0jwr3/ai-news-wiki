## Explicit loops and configurable endpoints

A robotics programming argument and a small Datasette release favor visible control boundaries.

A long-time FIRST Robotics mentor proposes Periodic-Oriented Programming: keep robot behavior readable in a top-to-bottom periodic loop, with a small number of explicit subsystem boundaries rather than many command abstractions. Subsystem methods set desired state, while centralized periodic logic validates constraints and updates hardware consistently. The argument is aimed at teaching and maintaining FRC robots, drawing on the author’s own experience. Its safety benefits depend on implementing those boundaries correctly; one function or fewer abstractions does not by itself prove a robot safe or make this the right structure for every application. ([read more](../summaries/39678c43afdc.md)).

Simon Willison announces OpenAI-compatible endpoint support in datasette-llm 0.1a11, the configuration layer used by other Datasette plugins. This lets a Datasette application select a locally or remotely hosted model through the same API-style interface. The example combines Datasette Agent with a local model server. Compatibility with the protocol is the key addition, not a claim that every model supports the same tools, performs equally well or keeps data local when pointed at a remote endpoint. ([read more](../summaries/6e370e2d53b1.md)).
